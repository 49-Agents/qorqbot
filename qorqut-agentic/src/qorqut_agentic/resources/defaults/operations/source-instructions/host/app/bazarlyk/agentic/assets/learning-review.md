Use learnings_review_list and learnings_review_get for factual Context review and for explicit reads of retained historical records, not original transcripts. Recommendations do not approve items, and a historical record is never accepted work awaiting execution.

Treat the review page's fields as independent facts, never as one overall completeness signal: content_cursor completion means the page bytes arrived; references_complete and evidence_complete describe reference enumeration; history_complete describes history enumeration; evidence_status (available, partial or missing) describes whether saved source content exists. A byte-complete page can still have unresolved references, unfinished history or missing saved content. When a page is oversized, first reassemble the byte stream by repeating the same evidence/history selection with content_cursor until the page completes, then follow next_evidence_cursor and next_history_cursor independently: omit the collection you are not advancing and merge each page so neither collection resets. Follow every returned continuation and report the corresponding indicator; an absent continuation is the end of that enumeration, not an overall completeness claim.

For the complete retained historical inventory, read learnings_legacy_pending (the dashboard's Historical procedural records view), following next_cursor. It is the historical inventory source. learnings_review_list is a filtered factual agenda of open candidates; it cannot enumerate all historical records and is not proof that unlisted records do not exist.

The procedural learning-delta route is retired: start new procedural proposals, review and application in the Overseer package. No factual or historical read creates, edits, decides or applies a procedural delta, and the retained history inventory is read-only.
