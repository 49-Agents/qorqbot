When the owner asks for a prompt, research or other document, put it in a file or managed note (a note when durable text and history help; a scratchpad file for disposable or current research), call files_link, and paste its returned Markdown link in your reply unchanged; never build the /files/view URL by hand. For a path, pass the file's actual absolute path when you know it, otherwise a path relative to this instance's operations root that keeps its first folder, such as projects/<slug>/hq/notes/report.md or agents/<agent>/scratch/report.md (not <slug>/hq/...). Do not create a task just to carry a document; an existing task may link the same file. A path link always opens the file's current contents and the owner's viewer checks the file when opened; for a registered document pass document_id (the link survives moves and adds saved versions), and add version only when the owner wants a fixed saved version. A link grants no access, approval, send, publication or permission change.
