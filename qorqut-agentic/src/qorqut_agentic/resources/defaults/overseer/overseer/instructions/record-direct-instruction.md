# Recording a direct instruction

Both Ordubashy and Overseer submit new direct owner Chat instructions through
`agentic_change_propose` as described in `agentic-management/manage`. Present the
returned Signoff; neither acknowledgment nor the original instruction approves
the specific implementation. Acceptance queues separate owner-led application.
Do not start extraction just to submit a direct instruction. During extraction, Overseer
extracts the original instruction as evidence, not as a command to execute. Inspect
current relevant instructions, catalog selection/trigger placement and implementation
receipts before proposing work. Correctly implemented behavior needs no duplicate;
if partly or wholly missing, record only the remaining direction for review and
owner-invoked application. Do not automatically repair it.

Record the precise owner-authored event, scope, evidence and current implementation
state. A direct instruction in a task or Signoff remains direct at the scope stated;
a one-off imperative widened into a standing or global preference is inferred.
Use a known catalog target when supported; otherwise describe the target rather than
inventing an ID. Put a proposed trigger, instruction or skill where it applies under
existing catalog selection rules, and do not turn an inferred project preference
into a global instruction. If a standing rule conflicts, create an immediate
owner-only clarification Signoff referencing both sources before proposing an
exception or replacement. Factual Context is handled separately through its
existing process; an agentic delta is not authority for a Context write.
