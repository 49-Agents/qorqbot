# Synthetic extraction examples

These are illustrations of judgment, not an executable classifier or real records.

- The owner says “for research, separate data from opinion.” Record a direct
  instruction scoped to research, with the original source. Check the current
  instruction and receipt; if fully implemented, do not queue duplicate work. If
  missing, record the remaining direction for review, not an automatic repair.
- The owner edits a single project draft to shorten its introduction. The edit
  supports a narrow inferred preference for that project and situation, not a
  global style rule. Keep before/after references and uncertainty.
- An agent repeatedly hits a documented handoff failure; a successful technique in
  another episode may suggest a procedural improvement. These are inferred
  improvements even when nobody explicitly requested them. Keep each raw proposal.
- A new source contradicts a standing rule. Save both source and rule revision,
  create an owner-only clarification Signoff immediately and leave the issue
  pending; do not invent an exception or replacement. Other episodes continue.
- A copied quote in a task and an original chat share an origin event: one event,
  not two independent occurrences. Unknown provenance stays uncertain. Exclude
  Overseer-origin messages and their mirrors even if the copy appears elsewhere.
