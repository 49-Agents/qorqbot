# v1.3 role sources

This document is the contract for what the role sources contain, what was removed, what is
unchanged and what the host must change. It is source documentation: **It publishes, adopts,
prepares and reloads nothing.** Published role versions stay immutable and earlier role
and plugin artifacts remain recoverable from Git history.

## Versions

Changed package contents need a new manifest version, so every role whose package bytes
changed moved.

| Package | Base | Now | Why |
|---|---|---|---|
| `roles/ordubashy/` | 1.65.0 | 1.68.0 | 10 specialist skills and 48 grants removed, `outreach` connection removed, brief and 16 shared skills edited; 1.68.0 (v1.32) moves email to Email Management and adds `calendar` |
| `roles/global-worker/` | 1.4.0 | 1.5.0 | 4 marketing skills and the `outreach` connection removed, brief sentence removed |

permanent worker) and Learning Applier. Their learning permissions, restrictions, review
procedure and Signoff rules are unchanged; no Overseer behavior was added or altered.

Kept skills: `action-recording`, `business-operations`,
`business-tables`, `chat-references`, `context-relationships`, `ecosystem-review`,
`learning-application`, `managed-browser-control`,
`ordubashy-browser-control`, `operations-delegation`, `owner-focus`, `owner-input`,

(`context_*`, `notes_*`), tables, routines, browser and worker management grants are unchanged. Owner-memory guidance uses the ordinary shared

Project notes are ordinary project documents: `business-operations` has a "Project notes"
section (explicit `target_business_id`, ordinary document tags, distinct from private agent
notes and the owner journal, no categories, no extra worker grants).

## Shared reminders (Ordubashy 1.73.0, global-worker 1.7.0, Learning Applier 1.17.0)

One host reminder service replaces the Telegram-backed owner reminder for the owner, Ordubashy and
every other agent. The existing `owner-reminders` skill (same id and path, so there is one copy and
no per-role duplicate) is rewritten in place as shared guidance, and global-worker and Learning
Applier now select it. Each role grants the seven operations as ordinary allows: `reminders_create`,
`reminders_get`, `reminders_list`, `reminders_update`, `reminders_snooze`, `reminders_dismiss` and
`reminders_cancel`. Ordubashy also keeps `owner_reminder`, which the host keeps as an owner-targeted
wrapper over the same service; the other roles never held it and do not receive it.

The grant does not widen management. The host decides per call: the owner and the configured
Ordubashy manage any recipient; every other agent manages only reminders addressed to itself,
whoever created them. The skill states this and tells other agents to ask Ordubashy to remind
someone else.

The skill covers: recurrence as a five-field cron with an IANA timezone (the host reuses the Routines
calendar), one card per recurring reminder, one notification per scheduled occurrence and latest-only
catch-up after downtime; stable `reminder_id` through updates; snooze (suppresses repeats, then the
original schedule resumes), dismiss of the current occurrence only (`occurrence_id` plus `revision`)
and cancel of the whole series; explicit `time_critical`; focus-aware delivery that is a notice and
never a focus switch or authorization; inbox acknowledgement that does not dismiss; and agent
dismissal once the action is captured as tracked work (for Ordubashy, on Attention before
execution). It promises no exact-time execution. Ordubashy 1.73.0 is built on the current 1.72.3
source and keeps its browser-management grant, protected supplier prose and public wording; only the
one-line reminder pointer in the brief was replaced, by a slightly shorter one, so the combined brief
(9,989 characters) stays within its 10,000-character limit.

Source activation steps for a future release (none performed here):

1. The host must register `reminders_*` and keep `owner_reminder` as the compatible wrapper before
   any of these roles can be published; the role source grants nothing by itself.
2. Publish the three new role versions through the normal Signoff-gated publication and adoption,
   keeping profile overrides and plugin pins. Published versions stay immutable; do not rebuild an
   older version from this source, because the shared skill changed in place.
3. Refresh the projected `bazarlyk-role-owner-reminders` skill for all three roles, and any live
   authored instruction copy that mentions reminders, through the normal expected-hash authoring
   path. Existing native sessions do not reread instructions until their next context refresh; do
   not claim otherwise or restart them for this.
4. Remove or replace any live instruction copy that still says an update returns a new id or that
   recurrence is unavailable.

## Checks

`python3 -m unittest discover -s tests` is source-only. It checks the three manifests and their
versions, grants and skills; that every packaged skill is selected and every selected path
exists; skill names match `bazarlyk-role-<id>`; briefs stay within 10,000 characters; the
retired roles, skills and operations are absent; no default manifest selects or grants optional
connector material; and the retained behavior (project creation, Focus, owner input, browser,
email, learning review) keeps its contract phrases. The Telegram skill's own contract phrases are
checked where it now lives, under `optional/telegram/`.
