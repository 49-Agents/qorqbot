# v1.3 role sources

This document is the contract for what the role sources contain, what was removed, what is
unchanged and what the host must change. It is source documentation: **It publishes, adopts,
prepares and reloads nothing.** Published role versions stay immutable and earlier role
and plugin artifacts remain recoverable from Git history.

## Versions

Changed package contents need a new manifest version, so every role whose package bytes
changed moved.

| Package | Base | Now | Why |
|---|---|---|---|
| `roles/ordubashy/` | 1.65.0 | 1.68.0 | 10 specialist skills and 48 grants removed, `outreach` connection removed, brief and 16 shared skills edited; 1.68.0 (v1.32) moves email to Email Management and adds `calendar` |
| `roles/global-worker/` | 1.4.0 | 1.5.0 | 4 marketing skills and the `outreach` connection removed, brief sentence removed |
| `roles/learning-applier/` | 1.12.0 | 1.13.0 | `subscriptions_*` grants removed, marketing-production sentence removed from the brief, shared skills edited |

## Kept

Three roles: Ordubashy (the general coordinator), the global worker (the general, repeatable
permanent worker) and Learning Applier. Their learning permissions, restrictions, review
procedure and Signoff rules are unchanged; no Overseer behavior was added or altered.

Kept skills: `action-recording`, `business-operations`,
`business-tables`, `chat-references`, `context-relationships`, `ecosystem-review`,
`learning-application`, `managed-browser-control`,
`ordubashy-browser-control`, `operations-delegation`, `owner-focus`, `owner-input`,
`owner-journal`, `owner-reminders`, `project-creation`, `service-provisioning` and
`telegram-owner-communication`; v1.32 adds `calendar` and removes `business-email-setup` and
`fastmail-account` (below). Journal, reminders, Focus, Telegram, Projects, calendar,
Cloudflare, Tasks, Signoffs, Context (`context_*`, `notes_*`), tables, routines, browser and
worker management grants are unchanged. Owner-memory guidance uses the ordinary shared
Context tools (`owner-journal` no longer points at a separate Personal Context).

Project notes are ordinary project documents: `business-operations` has a "Project notes"
section (explicit `target_business_id`, ordinary document tags, distinct from private agent
notes and the owner journal, no categories, no extra worker grants).

## Content guidance

The `content-creation` role skill is no longer a bundled role pack. Its complete production
guidance moved to `qorqut-content` (`skills/content-creation/SKILL.md`) with provenance, and
it refers to the pinned content-library skills by name rather than by absolute path. The
founder-oriented `pull-strategy` skill only pointed at the separate `right-framework-of-thinking`
plugin and was retired; content demand thinking stays in the content-library
`content-demand-thinking` skill. No publishing or SEO adapter was recreated.

## Host dependencies (not edited here)

The host must change in the slice that owns it; this repository only stops publishing:

1. Stop treating `founder` and `global-marketing` as role ids: `agents/roles.py`
   (`FOUNDER_ROLE`, `GLOBAL_MARKETING_ROLE`), `agents/global_peers.py` (`PEER_ROLES`),
   `bootstrap/preparation.py`, `composition/policy.py`, `release_worker/role_adoption.py`
   (`CONVERSIONS`) and the founder-retirement adoption path.
2. Stop pinning the old package versions (for example `release_worker/v12_role_adoption.py`
   pins Ordubashy 1.65.0 and founding plugin 0.3.0) and the host tests that pin them; adoption of
   1.68.0 / 1.5.0 / 1.13.0 is a separate owner-authorized release step.
3. Stop expecting the `outreach` connection from these roles (`catalog/packages.py`
   still allows it in the enum) and the `founding` plugin and its validators.
4. Operations the roles no longer grant (`ledger_*`, `metrics_*`, `products_*`,
   `subscriptions_*`, `daily_report_*`, `personal_context_*`, `campaign_*`, `logs_*`,
   `stripe_reader_get`, `signoffs_reddit_approve`) are host or other-slice removals; no role
   here refers to them.
5. Role skills are projected as `bazarlyk-role-<id>`; the removed skills must stop projecting,
   and the content-creation validators in the host (`agents/content_creation.py`) belong to the
   content extension, not the role projection.
6. Project notes follow the ordinary project-notes contract: the host must accept
   `target_business_id` for creating, listing and mutating a project note, ordinary `tags` metadata
   with a `tag` list filter, and reject ambiguous agent-note selectors; the category enum,
   `write_business_strategy` and pinned-note injection go away. The role text states exactly that
   contract and relies on no other argument.
7. `marketing-browser` appears in host browser targets; the Chat references example in
   `chat-references` no longer names it (`browser_id="<id from action=list>"`).

## CRM operations

Ordubashy 1.70.0 and global-worker 1.6.0 grant the host's CRM operations. They are source defaults only:
each is bounded by the existing operation it builds on, so the host denies it whenever that base grant is
denied, missing or stricter (Signoff), and an explicit deny on the new name always wins.

| Role | New default grants | Bounded by |
|---|---|---|
| Ordubashy | `crm_entries_list` | `tables_rows_list` |
| Ordubashy | `crm_entries_add`, `crm_entries_update`, `crm_entries_remove`, `tables_comment` | `tables_rows_write` |
| Ordubashy | `tables_thread_get`, `tables_follow` | `tables_get` |
| Ordubashy, global-worker | `crm_activity_list` | `tasks_get` |
| Ordubashy, global-worker | `crm_activity_record` | `tasks_comment` |

The worker receives the two Task-based names only, never a Table operation. The Global Table namespace keeps its
existing rule: only the standing Global roles (Ordubashy) hold Table defaults there. The `business-tables`
skill and the Ordubashy brief describe the tools; nothing is published, adopted or granted live by this source.

## Attention board (Ordubashy 1.72.0)

The owner's board is shown as Pinned and keeps its existing `focus_*` operations. Ordubashy's own
commitments move to the host's separate Attention board; the role source declares the frozen
operations as ordinary allows: `attention_get`, `attention_add`, `attention_remove`,
`attention_focus_set`, `attention_focus_clear` and `attention_workflow_update`. `workers_list`
reads the Worker candidates next to the existing `assignees_list`. The native client's exact-run
start/resume/pause synchronization uses `attention_workflow_context` and `attention_workflow_sync`,
declared as ordinary allows; they are coordination reads and association writes, never engine
control or a bypass of the work's approval. The brief requires an existing
board Task before any work beyond ordinary conversation, keeps the precise focus and atomic Intent
current, leaves Done visible until the owner removes it, keeps Worker edits separate from
delegation messages, and records a blocked workflow episode so it can be detached after its grace
period. Global workers and Learning Applier keep their current-work procedure unchanged. Nothing
is published, adopted or granted live by this source: the host must register those operations
first, and publication/adoption remain separate owner-authorized release steps.

## Checks

`python3 -m unittest discover -s tests` is source-only. It checks the three manifests and their
versions, grants and skills; that every packaged skill is selected and every selected path
exists; skill names match `bazarlyk-role-<id>`; briefs stay within 10,000 characters; the
retired roles, skills and operations are absent; and the retained behavior (project creation,
Focus, Telegram, owner input, browser, email, learning review) keeps its contract phrases.
