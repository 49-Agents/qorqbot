## Implementation boundary

- Both concrete adapters accept explicit managed HOME, workspace and immutable
  agent/conversation/recovery/environment/boot/run identities. Generated
  AGENTS.md/CLAUDE.md refer to authored persona.md/memory.md and describe browser
  action/file-path intent. Preparation never reads or seeds authored files or
  credentials. Existing authored config or changed generated bytes cause a
  conflict instead of replacement.
- Core/browser URLs and headers are caller inputs and remain separate native
  MCP registrations. Generated files have mode 0600. Dirfd-based access rejects
  symlink traversal; per-root locks serialize refresh. Each file is installed by
  fsync/replace/directory-fsync, with the hash manifest installed last. This is
  individual-file atomicity, not a multi-file transaction. An identical retry
  reconciles an interrupted installation; concurrent native readers require
  later runner orchestration.
- Hooks are configured only when the caller supplies a real sink argv. Its
  environment names a generated immutable per-run binding file. No stub hook
  executable or in-memory durability claim exists. SessionEnd translates to
  unknown activity, not proof that the native process exited.
- Launch results contain argv/cwd/environment and setup requirements, and never
  execute them. Claude uses its exact reserved or resumed UUID. Codex starts
  without inventing a native UUID, or resumes an exact supplied UUID; no latest
  picker, prompt injection, cross-provider replay or restoration packet exists.
- Discovery reads only managed native source directories. It returns raw path,
  inode/device, observed size, binding, and byte-coordinate/hash ownership
  evidence. It does not parse/project conversation, deduplicate equal messages,
  allocate durable source IDs or copy transcripts. A synthetic 9 MiB record and
  partial tail retain the bound raw descriptor with metadata-scan gaps.
