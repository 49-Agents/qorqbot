# Contributing

Use a focused change with a concise explanation and the checks that demonstrate
its behavior. Include documentation when a user-visible operation changes.
Keep credentials, personal records, local configuration and machine paths out of
code, examples and screenshots. Use synthetic examples.

Developer tests and fixtures are retained privately and excluded from this
publication repository. Release workflows check package builds, contents and
lifecycle behavior.

## Rights and license

Only submit work you have the right to contribute. Preserve existing third-party
copyrights, licenses and provenance. Identify copied or adapted material and its
source in the pull request; do not relabel it as first-party code.

Contributions to first-party files are offered under those files' existing
license, including the two-year Apache 2.0 conversion. Contributions to a
separately licensed component follow that component's license. This does not
transfer copyright ownership or, by itself, grant the maintainer the right to
issue a separate commercial license for another contributor's copyright.

Before accepting an external contribution that will need separate commercial
licensing, the maintainer must obtain the relevant contributor permission.
Do not imply that a normal commit sign-off is a copyright assignment or a
commercial-relicensing agreement.

Use the supported versions and standard tools documented by the project. Changes
to optional integrations must keep core usable when the integration is absent.
