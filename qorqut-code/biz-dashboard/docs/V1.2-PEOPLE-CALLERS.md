# People readers

People pages use the published graph response (`kind: node`, `node:` references and array attributes). They select only nodes explicitly carrying `basic_entity_type: [person]`; a name never creates a classification. All search pages keep the same published revision and exact returned cursor, using the shared response validator. Missing or incomplete reads never become an empty People list.

Upload suggestions read the same global graph through the selected authorized scope. Selecting a graph person supplies a source participant name, never an invented document identity. Existing raw People detail links remain raw scoped document reads and edits; they do not redirect by a matching name or offer the removed model summary command.

No IDs or raw errors are added to the UI. Validation: JS syntax checks and `node tests/test_people_published_contract.js`, using accepted published response fixtures with revision/cursor, explicit classification and cancellation cases.
