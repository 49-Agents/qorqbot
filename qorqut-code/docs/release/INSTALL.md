# Release-worker installation

This guide describes how the release worker (`qorqut.release_worker`, see the
[release guide](README.md)) is installed from an assembled immutable artifact. It
describes the worker's own installer only (`tools/release_worker/install.py`). Local source export, environment
preparation and manual startup of a Qorqut instance are in [Installation](../INSTALLATION.md); this guide is not
an installer or upgrader for the host, which this source does not supply, and it claims no completed installation or
rehearsal.

An installation uses a stable launcher in `~/.local/bin` backed by a validated, immutable
release artifact and its compatible `.venv`; it never imports a development checkout.

Verify the active installation:

```sh
release-worker --version
release-worker --help
```

`--version` prints the release identifier, absolute source artifact, recorded
source commit, Python executable, worker-file digest and installed docs path.
`--docs-path` prints the stable installed directory containing this guide and
the release README. `--installer-path` prints the installed updater preserved
alongside the active version. A missing metadata file, source artifact, worker
module, Python executable or docs directory fails with a clear error before any
worker command runs.

## Updating an installation

The installation metadata is `~/.config/qorqut/release-worker.json`; its
version records live under `~/.local/share/qorqut/release-worker/versions/`.
The launcher is generated by the versioned installer
`tools/release_worker/install.py`. To activate a later approved release, run
the installer with the assembled release artifact, its full recorded source
commit, and an explicit `--activate`:

```sh
python3 "$(release-worker --installer-path)" \
  --source /absolute/path/to/releases/<release>/qorqut-code \
  --version <release> \
  --commit <full-source-commit> \
  --provenance-repository /absolute/path/to/qorqut-code \
  --trusted-ref origin/main \
  --activate
```

The installer validates the worker module and compatible Python environment,
requires every worker Python file to match the exact commit in the trusted Git
repository, requires that commit to be an ancestor of the trusted ref, records
the source file hashes, and refuses ambiguous version updates. The selected
source is a release artifact; never point it at a development checkout. Keep the
installer and this guide together when changing the installation contract; update
the workspace startup instructions and the local `qorqut-release` skill at the same
time. Installation changes do not merge, deploy, migrate, restart services, publish
roles or adopt plugins.

Worker source fixes, such as readiness polling and bulk artifact verification
(see the [release guide](README.md)), do not update the installed launcher. They
take effect only after the merged commit is assembled into an immutable artifact
and activated with the installer above; a task worktree is never the active worker.

The installer import check and each worker invocation use a fresh private Python
cache location with cache writes disabled. Existing source-backed bytecode is
not executed, and service caches are left untouched. Source paths remain intact
so package resources resolve normally.

## Worker versions supporting creative-session bindings

Persistent experience support adds trusted worker modules without changing the
versioned installer's all-Python-file provenance contract. Validate those modules
and the matching [binding guide](EXPERIENCE-BINDINGS.md) with the immutable artifact;
activate only after approved merge through this installer. A task worktree is not
an installed worker. NFS mounts, independent-target restore evidence, selected data
bindings, gallery migration and profile adoption are separate installation steps.
This source installs none of them and changes no local startup copies.
