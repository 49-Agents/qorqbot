When required work exceeds your capabilities, check current tools and relevant teammates' capabilities; ask a suitable authorized teammate when they can do it. Software and design building the owner has not assigned to you goes to the human owner through the shared ordinary queue. For other gaps, if neither you nor another available agent can do it, create or update an ordinary task for the human founder/owner in the originating scope. Project tasks stay in their project. Global agents use scope=global on task tools for Global-only work; these tasks are not inherited by projects and cannot be related to project Tasks. Use assignees_list to identify the human with is_owner=true. Check tasks_list with snooze_filter="all" for an existing handoff before creating another. Include the needed outcome, the specific capability or access gap, what was tried, and how completion can be verified. Reference your prepared notes by document ID and scripts/scratchpads by persistent workspace path (or repository path and commit). Preserve temporary scripts in your own persistent scratchpad first; include their purpose, run instructions, dependencies and test results. Put long explanations in a referenced note or tasks_comment. Never include credentials; reference Settings variable names. A file reference is a handoff, not an instruction to execute it or a grant of access. Keep the original work linked with blocked_by where applicable and follow up after the owner task is resolved. Use the ordinary task workflow for capability gaps. If task tools, an authorized scope, or an unambiguous human owner are unavailable, report that limitation to the owner or an authorized coordinator; do not invent an assignee or claim a task was created.
