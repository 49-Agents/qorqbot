# WhatsApp connector

This package supplies the private reader and the owner-approved `whatsapp_send` operation. It is built into every Qorqbot download (Linux x86-64, Windows through WSL2, Mac on Apple silicon) with the native helper inside its wheel; users do not need Go. The launcher selects `qorqut_whatsapp.extension:create` for new installations and adopts it once, offline, for existing ones. It stays dormant: nothing starts the helper or contacts WhatsApp until the owner asks Ordubashy to set it up or uses Settings > Connections. No terminal step is needed. Core works without the package; a runtime with no helper for its platform starts without it.

Setup binds the reader to the Global Ordubashy who started it, shows the pairing QR only in the owner's dashboard, and after the scan finishes managed sending by itself. The `install-reader` and `pair` commands remain for setting up by hand with Qorqbot stopped. All new helper, account, socket and log files stay inside the instance folder; a long installation path can exceed Linux's Unix socket limit and is refused. Pairing is an owner action and contacts WhatsApp; package installation does not.

Read-only version 1 bindings cannot send. Existing version 2 managed-send bindings retain their authenticated private socket, secret and exact opaque account identity. See [the transport contract](native/README.md) for explicit managed-send setup. Every send still requires a granted global manager, a separate owner Signoff, current account/recipient validation and a durable background job. The agent MCP contains only `whatsapp_read`; a policy override cannot bypass approval. Ambiguous sends use receipt-only recovery, never an automatic resend.

Do not uninstall while provider jobs are pending. Uninstalling does not delete historical Signoffs/jobs or account files. Private history stays restricted to the owner when the extension is absent. Profiles retaining a provider operation grant must be reconciled through the supported offline configuration path before removal; unknown grants fail closed.

Build with `python tools/build.py --work /absolute/private/build-directory`. It uses the pinned official Go container (Linux) or the local Go toolchain (`--target macos-arm64`, optionally `--sign-identity`), verifies module checksums, runs the race tests and packages the helper plus dependency notices and its corresponding-source archive. `native/` and `tests/` remain development-only. The package's indexed guidance and rendering source are independently verified against the installed wheel RECORD when no source checkout is present.
